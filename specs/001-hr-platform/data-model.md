# Phase 1 Data Model: CDS Business HR Platform

Entities map to the spec's Key Entities. All models use a shared `TimeStampedModel`
(`created_at`, `updated_at`). Money/PII notes are absent — no payroll fields exist.

## Entity: User (accounts)

| Field | Type | Constraints / Notes |
|-------|------|---------------------|
| email | EmailField | unique, login identifier |
| password | (hashed) | set via `set_password`; temporary passwords generated by HR |
| role | CharField(choices) | `EMPLOYEE` \| `MANAGER` \| `HR` — exactly 3 (constitution I) |
| is_active | BooleanField | deactivation disables login without deleting (FR-045) |
| must_change_password | BooleanField | forces password change before other access (FR-007) |
| manager | FK → User, null | reporting line; only meaningful for EMPLOYEE/MANAGER |

Validation: `manager` may not create cycles; a user's role change is an audited admin action.

## Entity: EmployeeProfile (accounts)

OneToOne with User. Field set is fixed but each field is flagged editable-by-employee vs
HR-managed:

| Field | Editable by employee |
|-------|----------------------|
| first_name, last_name | no (HR-managed) |
| phone, address, personal_email | yes |
| job_title, department, hire_date | no (HR-managed) |

Server enforces the split per-field (FR-010) — the update serializer whitelists
employee-editable fields for EMPLOYEE callers.

## Entity: Workflow (workflows)

| Field | Type | Notes |
|-------|------|-------|
| name | CharField | e.g. "Standard manager approval" |
| steps | reverse FK → WorkflowStep | ordered; ≥1 step |

## Entity: WorkflowStep (workflows)

| Field | Type | Notes |
|-------|------|-------|
| workflow | FK → Workflow | |
| order | PositiveSmallInt | sequence; unique per workflow |
| actor_role | choices | `MANAGER` \| `HR` (employee never reviews own item) |
| require_comment_on_reject | Boolean | comments policy per step |
| require_comment_on_return | Boolean | |

Editing a workflow in use: permitted for future items only — in-flight items snapshot
`current_step`/workflow at submission (FR-022 no retroactive changes).

Step actor resolution: `actor_role=MANAGER` resolves to the submitter's current manager at
read/review time — deactivating or replacing a manager re-routes pending items
automatically. `actor_role=HR` scopes visibility to items with an assigned HR step.

## Entity: RequestType (requests)

| Field | Type | Notes |
|-------|------|-------|
| name | CharField | unique, e.g. "Annual Leave" |
| workflow | FK → Workflow | which review chain instances follow |
| fields_schema | JSONField | ordered field defs: `{key, label, type, required}` where type ∈ text/number/date/choice |
| allow_attachments / require_attachments | Boolean | per-type attachment rules (FR-012) |
| is_active | Boolean | inactive types can't be submitted |

## Entity: Request (requests)

| Field | Type | Constraints / Notes |
|-------|------|---------------------|
| request_type | FK → RequestType | |
| submitter | FK → User | indexed |
| values | JSONField | answers keyed by RequestType.fields_schema |
| comment | TextField | free text |
| status | CharField | `DRAFT`? — no: `PENDING` \| `IN_REVIEW` \| `RETURNED` \| `APPROVED` \| `REJECTED` \| `WITHDRAWN` (see transitions) |
| current_step | PositiveSmallInt | step index into workflow |
| workflow_snapshot | JSONField | steps copied at submission |
| submitted_at | DateTime | null until submitted |

Indexes: `(submitter, status)`, `(status, current_step)`, `submitted_at`.

## Entity: Attachment (requests)

| Field | Type | Notes |
|-------|------|-------|
| request | FK → Request | required — attachments are request-scoped this iteration |
| file | FileField | storage = private MEDIA_ROOT |
| original_name, content_type, size | | validated: allowlisted type, ≤10 MB |
| uploaded_by | FK → User | |
| removed_at | DateTime, null | soft-delete marker — settable only while parent editable |

Download authorization delegates to parent item permission (FR-029). Attach/remove
permitted only while the parent item is editable (PENDING before first reviewer action,
or RETURNED). There is no server-side DRAFT — unsubmitted composition is client-side
state only. Removed attachments (`removed_at` set) are excluded from views and downloads;
the record and file are retained (FR-045).

## Entity: Notification (notifications)

| Field | Type | Notes |

Never created for the actor's own action (FR-034).

## Entity: AuditEntry (audit)

Append-only; no update/delete API or admin path.

| Field | Type | Notes |
|-------|------|-------|
| actor | FK → User | who performed the action |
| action | CharField | submit/approve/reject/return/resubmit/withdraw/… |
| item_type / item_id | generic ref | polymorphic target |
| from_status, to_status | CharField, null | |
| comment | TextField, null | reviewer comment where applicable |
| created_at | DateTime | timestamp — immutable |

## Status Lifecycle (shared by Request & Timesheet)

```text
                     ┌──────────────┐
                     │   PENDING    │ (submitted, awaiting first step)
                     └──────┬───────┘
             reviewer acts  │  submitter withdraws
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
        (next step     ┌─────────┐   ┌───────────┐
         exists?)      │RETURNED │   │ WITHDRAWN │ (final)
              │        └────┬────┘   └───────────┘
       approve│             │ resubmit → PENDING (same step)
              ▼
   ┌────────────────────┐
   │ IN_REVIEW (n>1)    │── repeat per step ──┐
   └────────────────────┘                      ▼
                    ┌──────────────────────────────────┐
                    │ APPROVED / REJECTED (final)      │
                    └──────────────────────────────────┘
```

- `PENDING`/`IN_REVIEW` → `WITHDRAWN` only by submitter, only while no decision actioned
  on the current step (FR-023). Withdraw race resolved by first-recorded transition.
- `RETURNED` → `PENDING` on resubmit; each cycle audited.
- Multi-step: approve at step N < last → `IN_REVIEW`, `current_step` = N+1, next actor
  role notified. Approve at last step → `APPROVED`. Reject at any step → `REJECTED` (final).
- Approved items are read-only (FR-016, FR-027).

Note: no `DRAFT` status exists — `POST /api/requests/` creates an already-submitted
`PENDING` item; "drafting" happens client-side before submission.

## Derived Authorization Scopes

| Role | Requests/Timesheets visible | Actions |
|------|-----------------------------|---------|
| EMPLOYEE | own only | create, submit, withdraw, resubmit, edit profile (own fields), change password |
| MANAGER | own + direct reports' items | all employee actions + approve/reject/return steps where actor_role=MANAGER |
| HR | items where an assigned HR step exists (pending/completed) + admin functions + aggregate dashboards | employee actions + administer users/types/workflows + act on steps where actor_role=HR |

# Appendix: Reports logical model (merged from `specs/archive/002-reports/data-model.md`)

No persisted report entities — computed views over `AttendanceSession`,
`Timesheet`, `Request`, `User`/`EmployeeProfile`, `AuditEntry`.

**Report keys**: `attendance | timesheets | requests | employees`.
**Filters**: `date_from`,`date_to` (ISO, `to ≥ from`), `employee` (in-scope id),
`department` (ci match), `status` (per-report whitelist), `request_type`
(requests only), `lang` (`en|ar`, exports), `fmt` (`xlsx|pdf`, exports).
**Scope**: `visible_employees(user)` + `scope_items`/`scope_attendance`;
exports share the identical scoped queryset.
**Summary**: aggregates over the entire filtered set (not the page).

Row shapes:
- `attendance` (per employee-day): employee_*, date, check_in, check_out,
  worked_seconds/hours, sessions, status(PRESENT|IN_PROGRESS),
  required/difference hours = null (`*_available:false`).
- `timesheets` (per timesheet): employee_*, `week_start`(Mon), `week_end`(Sat),
  `business_week_start`(Sun), logged_hours, status, status_group,
  current_actor_role, submitted_at, reviewed_at.
- `requests` (per request): employee_*, request_type(id+name), created_at,
  status, status_group, current_actor_role, current_step, total_steps.
- `employees` (per visible employee): employee_*, attendance_days,
  worked_hours, sessions, timesheets(+approved), logged_hours,
  requests_{total,pending,approved,rejected,cancelled}.

Invariants: every row passes caller scope; `status` carries internal enum
(`status_group` is display grouping only); honest unavailable metrics
(`null` + `*_available:false`); exports capped (xlsx 50k / pdf 2k rows).
